# Content architecture

## Archetypes
| Audience | Goal | Likely entry | Key question | Minimum convincing content |
|---|---|---|---|---|
| Senior public servant | Defensible direction | Insight / home | What controls this outcome? | Method, evidence status, usable output |
| Municipal CAO or planner | Reconcile target and delivery | OCP / fiscal | Can the plan be delivered? | Delivery trace, assumptions, proof artifact |
| Economic-development leader | Sequence action | Strategy | What can we control now? | Readiness screen, dependencies, roadmap |
| Labour/workforce leader | Protect a date | Labour insight | Which trade constrains delivery? | Decomposition, timing, model output |
| Resource/industry executive | Expose project dependencies | Resource analysis | What threatens the schedule? | Dependency register, scenario proof, contact path |

## Sitemap and flows
Home branches to What we do, Selected work and Insights; What we do branches to seven application pages; Insights branches to three articles; global utility pages and Contact remain available from the footer. Diagnostic tools remain at `/tools/*` but outside the public P01–P20 visual scope.

Primary flows are Home → What we do → application → Selected work → Contact; Insight → related application/proof → Contact; and Home → Selected work → application → Contact.

Deep links open with a unique H1, short summary, hierarchical breadcrumb, article metadata where applicable, an on-this-page outline for long pages, contextual related links from authoritative Markdown, and a decision-oriented close.
